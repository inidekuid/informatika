Kamu sudah bisa mencari satu per satu — sekarang kita tanya: bisakah lebih hemat?

Di pertemuan lalu, kita pakai pencarian sekuensial: periksa dari index 0, satu per satu, sampai ketemu atau habis. Cara ini bekerja di semua kondisi data.

Sekuensial (pertemuan lalu)

Cek index 0, 1, 2, … sampai ketemu. Selalu benar, tapi bisa panjang.

→

Binary search (hari ini)

Cek dari tengah, lalu buang separuh yang tidak mungkin. Bisa jauh lebih singkat — tapi butuh syarat.

Pertanyaan kunci hari ini: Kapan kita bisa menghindari mengecek satu per satu? Dan apa yang harus kita bayar untuk itu?

Navigasi: panah kiri/kanan, geser di layar sentuh, atau tombol di bawah.

Ingat kembali

Kasus terburuk sekuensial: element ada di ujung

Data: 2, 5, 8, 12, 16, 23, 38, 56, 72, 91 (10 angka, index 0–9).

Cari 91 (ada di index 9). Sekuensial harus mengecek index 0, 1, 2, …, 9 — 10 cek untuk 10 data.

Dalam kasus terburuk, sekuensial butuh sebanyak jumlah data. Untuk 1 juta data, itu bisa sampai 1 juta cek.

Bukan berarti sekuensial jelek — ia tetap benar di semua kondisi. Pertanyaannya: adakah cara yang lebih hemat tanpa mengorbankan kebenaran?

Permainan

Tebak angka 1 sampai 100 — strategi mana yang lebih cepat?

Temanmu memilih angka rahasia. Kamu menebak, ia menjawab "lebih besar", "lebih kecil", atau "tepat".

Strategi A — Urutan

Tebak 1, lalu 2, lalu 3, …

Seperti sekuensial: selalu maju satu langkah. Kasus terburuk: 100 tebakan.

Strategi B — Tengah

Tebak 50 → jika "lebih kecil", tebak 25 → jika "lebih besar", tebak 37 → …

Setiap jawaban membuang separuh. Kasus terburuk: 7 tebakan untuk 100 angka.

Jika angka rahasia adalah 73:

  • Strategi A: 73 tebakan — cek 1, 2, …, 73
  • Strategi B: 50 → 75 → 62 → 68 → 71 → 73 — 6 tebakan

Strategi B bisa jauh lebih hemat karena setiap jawaban membuang separuh kandidat yang tersisa. Inilah ide dasar binary search.

Keterangan: tebakan ke-1 = 50 (tengah 1–100), ke-2 = 75 (tengah 51–100), ke-3 = 62 (tengah 51–74), ke-4 = 68 (tengah 63–74), ke-5 = 71 (tengah 69–74), ke-6 = 73 (tengah 72–74). Total 6 tebakan.

Ide inti

Satu cek di tengah → separuh data langsung tersingkir

Data: 2, 5, 8, 12, 16, 23, 38, 56, 72, 91. Cari 23. Kita cek index 4 (nilai 16).

Pikirkan dulu: index mana yang sekarang pasti bukan jawaban?

Sekuensial — cek index 0

Nilai 2 ≠ 23. Satu angka tersingkir. Sisa: 9

vs

Biner — cek index 4

Nilai 16 < 23. Index 0–4 (5 angka) tersingkir. Sisa: 5

Perbandingan langsung

Setelah cek pertama — sudah terlihat bedanya

Sekuensial — cek index 0 (nilai 2)
Biner — cek index 4 (nilai 16)
Sekuensial: 1 angka tersingkir per cek.
Biner: ~separuh angka tersingkir per cek.
Dengan 10 data, separuhnya = 5. Dengan 1 juta data, separuhnya = 500.000.

Perbedaan ini berlipat setiap langkah — itulah yang membuat biner jauh lebih hemat pada data besar.

Syarat penting

Kita bisa buang separuh hanya jika data terurut

Pertanyaan kuncinya: mengapa nilai di tengah bisa memberi tahu kita tentang seluruh sisi kiri atau kanan?

✓ Data terurut naik

Cek index 4, nilai 16. Cari 23.

Karena data urut, semua angka di kiri index 4 pasti < 16 < 23. Kita yakin membuang 5 angka sekaligus.

✗ Data tidak terurut

Cek index 4, nilai 56. Cari 23.

Data tidak urut → angka di kiri bisa apa saja. 23 bisa saja ada di kiri. Kita tidak bisa membuang separuh dengan yakin.
Syarat yang tidak boleh dilanggar: Data harus terurut sebelum menggunakan binary search. Tanpa ini, hasilnya bisa salah — angka ada tapi dinyatakan tidak ada.
Langkah pertama

Dari mana mulai? Menentukan kiri, kanan, dan tengah

Sebelum memeriksa data, kita wajib menetapkan batas area aktif dan rumus menentukan nilai tengah.

Langkah 0 — Tetapkan batas awal

K
kiri = 0
Index paling pertama dari data (selalu 0).
R
kanan = panjang data − 1
Index terakhir. Pada 10 data: kanan = 10 − 1 = 9.

Index dimulai dari 0 sampai len(data) - 1.

Langkah 1 — Hitung index tengah

tengah = ⌊(kiri + kanan) / 2⌋
Di Python ditulis: tengah = (kiri + kanan) // 2

Kenapa pembulatan ke bawah (//)?
Jika jumlah data genap (index 0 sampai 9), (0+9)/2 = 4.5. Komputer tidak punya index 4.5, maka dibulatkan ke bawah menjadi index 4.

⚠️ Miskonsepsi Fatal: Yang Dijumlahkan Adalah NOMOR INDEX, Bukan NILAI Datanya!
Data: [2, 5, 8, 12, 16, 23, 38, 56, 72, 91] dengan index 0 sampai 9.
❌ SALAH: (2 + 91) // 2 = 46  (ini menjumlahkan angka di dalam kotak)
✓ BENAR: (0 + 9) // 2 = 4  (kita mencari alamat kotak tengah = index 4, isinya adalah 16)

🧮 Kalkulator tengah — coba sendiri

tengah = ⌊( 0 + 9 ) / 2⌋ = ⌊ 9 / 2⌋ = ⌊ 4.5 ⌋ = 4
Proses pencarian

Bagaimana angka yang dicari menentukan langkah berikutnya?

Misalkan angka yang kita cari adalah target (contoh: target = 23). Setiap kali index tengah didapat, bandingkan nilai di tengah data[tengah] dengan target:

1. data[tengah] == target

🎯 Ketemu! Nilai cocok dengan angka yang dicari. Catat index tengah dan selesai (break).

2. data[tengah] < target

Nilai tengah terlalu kecil. Karena data urut naik, seluruh sisi kiri pasti lebih kecil lagi. Buang sisi kiri:
kiri = tengah + 1

3. data[tengah] > target

Nilai tengah terlalu besar. Karena data urut naik, seluruh sisi kanan pasti lebih besar lagi. Buang sisi kanan:
kanan = tengah − 1

Mengapa harus + 1 dan − 1?

Karena index tengah sudah diperiksa dan terbukti bukan jawaban! Jika hanya ditulis kiri = tengah atau kanan = tengah, program bisa terjebak dalam loop berputar tanpa henti (infinite loop).

Kapan kita tahu angka TIDAK ADA di data?

Setiap langkah, area aktif menyusut. Jika target tidak ada, batas kiri akhirnya melompat melewati kanan (kiri > kanan). Area menjadi kosong (0 elemen) → angka dipastikan tidak ada!

Contoh runutan cari 23 pada [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]:

Kode Python

Binary search sebagai skrip lurus — tanpa def

Semua ditulis struktural: baris dijalankan berurutan dari atas ke bawah. Tidak ada fungsi (def), tidak ada pemanggilan — cukup while, if/elif/else, dan print. Salin ke binary_search.py, lalu jalankan.

Python
data = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
cari = 23
kiri = 0
kanan = len(data) - 1
langkah = 0
ketemu = False
while kiri <= kanan:
    langkah = langkah + 1
    tengah = (kiri + kanan) // 2
    print("Langkah", langkah, "| kiri", kiri, "| kanan", kanan, "| tengah", tengah)
    print("  data[", tengah, "] =", data[tengah], "vs", cari)
    if data[tengah] == cari:
        ketemu = True
        print("  Sama! Ketemu di index", tengah)
        break
    elif data[tengah] < cari:
        print("  Terlalu kecil -> buang kiri, kiri =", tengah + 1)
        kiri = tengah + 1
    else:
        print("  Terlalu besar -> buang kanan, kanan =", tengah - 1)
        kanan = tengah - 1
if ketemu:
    print("Selesai: ketemu di index", tengah, "dalam", langkah, "langkah")
else:
    print("Selesai: tidak ditemukan dalam", langkah, "langkah")
Mengapa tanpa def? Kode struktural lebih mudah diikuti saat baru belajar: alurnya terlihat utuh dari atas ke bawah. Setelah paham, barulah kode ini biasanya dibungkus menjadi fungsi agar bisa dipakai berulang.
Menjalankan kode

Jalankan, lalu baca hasilnya

Output di bawah adalah hasil nyata untuk cari = 23. Bandingkan dengan jejak langkah pada slide "Langkah demi langkah".

Cara membaca kodenya

1
kiri = 0, kanan = len(data) - 1
Tandai area awal: seluruh data (index 0 sampai 9).
2
tengah = (kiri + kanan) // 2
Cek titik tengah. // membulatkan ke bawah karena index tidak boleh pecahan.
3
kiri = tengah + 1 / kanan = tengah - 1
Buang separuh yang sudah pasti bukan jawaban. Inilah inti penghematannya.
4
while kiri <= kanan
Selama area masih berisi, ulangi. Jika kiri > kanan, area kosong → angka tidak ada.

Kapan memakai yang mana?

Sekuensial dan biner punya situasinya masing-masing

Kondisi Sekuensial Biner
Data tidak terurut ✓ Aman dipakai ✗ Hasilnya tidak bisa dipercaya
Data terurut, dicari sekali Bisa, tapi lebih banyak cek ✓ Lebih hemat
Data kecil (< 20 elemen) ✓ Cukup, kode lebih sederhana Bisa, tapi manfaat kecil
Data besar (jutaan elemen) Lambat di kasus terburuk ✓ Sangat signifikan efisiensinya
Data sering berubah ✓ Langsung dipakai Perlu sort ulang setiap ada perubahan
Keduanya benar pada kondisinya masing-masing. Pilih berdasarkan konteks, bukan berdasarkan mana yang "lebih keren".

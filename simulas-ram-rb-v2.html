Apa itu Round Robin?

Round Robin (RR) adalah algoritma penjadwalan CPU yang membagi waktu CPU secara adil kepada semua proses. Setiap proses mendapat jatah waktu tetap yang disebut time quantum. Jika proses belum selesai saat quantum habis, proses "dipaksa berhenti" (preempt) dan masuk ke belakang antrian.

🔤 Apa itu P1, P2, P3?

P1, P2, P3 adalah nama/label proses — singkatan dari Process 1, Process 2, dst. Dalam sistem operasi nyata, proses adalah program yang sedang berjalan di memori. Contoh:

  • P1 = Chrome membuka halaman web
  • P2 = Spotify memutar musik
  • P3 = Word menyimpan dokumen

Semua proses ini membutuhkan CPU, tapi CPU hanya bisa mengerjakan satu proses dalam satu waktu. Maka perlu penjadwalan!

⏱️ Apa itu Arrival Time?

Arrival Time = waktu saat proses pertama kali masuk ke sistem dan siap dieksekusi.

  • Arrival = 0 → proses sudah ada sejak awal
  • Arrival = 3 → proses baru muncul di detik ke-3 (misal: user baru membuka aplikasi)

Proses hanya bisa masuk antrian setelah arrival time-nya tercapai.

⚡ Apa itu Burst Time?

Burst Time = total waktu CPU yang dibutuhkan proses untuk selesai sepenuhnya.

  • Burst = 3 → proses butuh 3 unit waktu CPU
  • Burst = 8 → proses lebih berat, butuh 8 unit waktu

Di Round Robin, proses dengan burst besar akan mendapat banyak giliran karena tidak bisa selesai dalam satu quantum.

🔄 Apa itu Time Quantum?

Time Quantum = batas waktu maksimum yang diberikan CPU kepada setiap proses dalam satu giliran.

  • Quantum kecil → lebih responsif, tapi banyak perpindahan (overhead)
  • Quantum besar → lebih efisien, tapi proses kecil harus menunggu lama

💡 Analogi Sederhana

Bayangkan satu meja rias (CPU) dipakai bergantian oleh beberapa orang (proses). Setiap orang dapat jatah 3 menit (quantum). Kalau belum selesai dandan, harus pindah ke belakang antrian. Semua mendapat giliran yang adil.

🗂️ Fungsi OS yang Terlibat

  • Process Management — membuat, menjadwalkan, menghentikan proses
  • CPU Scheduling — memilih proses mana yang dieksekusi (Round Robin)
  • Memory Management — mengalokasikan RAM untuk proses, code, data, stack
  • Interrupt Handling — timer interrupt memicu preemption saat quantum habis
  • Context Switching — menyimpan/memulihkan register CPU lewat PCB

📐 Siklus Hidup Proses

Dalam simulasi ini, setiap proses melewati state berikut:

New / WaitingBelum tiba (arrival time belum tercapai)
ReadySudah tiba, menunggu giliran di ready queue + sudah ada di RAM
RunningSedang dieksekusi oleh CPU
SwappedDipindah dari RAM ke disk (swap out) karena RAM penuh
TerminatedSelesai — memori dibebaskan

🧠 Memory Management & Proses

Setiap proses yang berjalan membutuhkan ruang di memori (RAM). OS bertanggung jawab mengalokasikan dan mengelola memori ini.

📦 Apa yang Disimpan di RAM untuk Setiap Proses?

  • Code (Text) Segment — instruksi program yang akan dieksekusi CPU
  • Data Segment — variabel global & static
  • Stack — variabel lokal, parameter fungsi, return address
  • Heap — memori yang dialokasikan secara dinamis (malloc, new)
  • PCB (Process Control Block) — metadata proses: PID, state, register CPU, pointer ke memori, prioritas, dsb.

🔄 Apa itu Swapping?

Swapping adalah mekanisme OS memindahkan proses antara RAM dan disk (swap space):

  • Swap Out — proses yang sedang tidak aktif (menunggu lama di antrian) dipindahkan dari RAM ke disk untuk memberi ruang bagi proses lain
  • Swap In — saat proses mendapat giliran CPU lagi, OS memuat kembali proses dari disk ke RAM

Swapping terjadi karena RAM terbatas. Jika ada 10 proses tapi RAM hanya cukup untuk 4, sisanya harus "menunggu di disk".

⚡ Kaitan Swapping dengan Round Robin

  • Round Robin membuat banyak proses bergantian aktif — ini meningkatkan kebutuhan memori
  • Saat proses di-preempt (quantum habis), OS menyimpan state-nya ke PCB di RAM. Jika RAM penuh, PCB + data proses bisa di-swap out ke disk
  • Quantum terlalu kecil → context switch sering → swap in/out sering → thrashing (sistem lambat karena sibuk swap)
  • Quantum terlalu besar → proses menunggu lama → lebih banyak proses idle di RAM → boros memori

📐 Alur Lengkap: Scheduling + Memory

Apa yang terjadi saat context switch di Round Robin:

① Timer InterruptHardware timer mengirim sinyal bahwa quantum habis
② Save StateRegister CPU (PC, SP, flags) disimpan ke PCB proses berjalan di RAM
③ Swap Out (jika perlu)Jika RAM penuh, proses lama dipindah ke disk (swap space)
④ Swap In (jika perlu)Proses berikutnya dimuat dari disk ke RAM (jika sebelumnya di-swap)
⑤ Load StateRegister CPU dimuat dari PCB proses baru
⑥ ResumeCPU melanjutkan eksekusi proses baru dari posisi terakhir

📖 Glosarium Parameter & Istilah

Referensi lengkap semua istilah yang digunakan dalam simulasi.

Proses P1, P2, …
Program yang sedang berjalan dan membutuhkan waktu CPU. Setiap proses memiliki ruang memori sendiri.
Arrival Time AT
Waktu saat proses pertama kali masuk ke sistem dan siap dijadwalkan.
Burst Time BT
Total waktu CPU yang dibutuhkan proses untuk selesai sepenuhnya.
Memory Size Mem
Jumlah memori (RAM) yang dibutuhkan proses untuk berjalan.
Time Quantum Q
Batas waktu maksimum CPU per giliran. Inti algoritma Round Robin.
RAM Capacity
Total memori fisik yang tersedia untuk semua proses.
Ready Queue
Antrian FIFO tempat proses menunggu giliran CPU. Proses harus ada di RAM.
Context Switch
Perpindahan CPU dari satu proses ke lainnya. Menyimpan & memulihkan register via PCB.
Preemption
Pemaksaan berhenti pada proses yang sedang berjalan karena quantum habis.
Swap Out
Memindahkan proses dari RAM ke disk (swap space) karena RAM penuh.
Swap In
Memuat kembali proses dari disk ke RAM saat akan mendapat giliran CPU.
Swap Space
Area di disk yang digunakan sebagai perpanjangan RAM untuk menyimpan proses yang di-swap.
Thrashing
Kondisi sistem sibuk swap in/out terus-menerus sehingga kinerja menurun drastis.
PCB
Process Control Block — struktur data di RAM berisi info proses: PID, state, register, pointer memori.
Completion Time CT
Waktu saat proses selesai sepenuhnya. CT = waktu unit terakhir dieksekusi.
Turnaround Time TAT
Total waktu dari tiba hingga selesai. Rumus: TAT = CT − AT.
Waiting Time WT
Total waktu menunggu di antrian. Rumus: WT = TAT − BT.
Response Time RT
Waktu dari tiba hingga pertama dieksekusi. Rumus: RT = First Run − AT.
CPU Utilization
Persentase waktu CPU aktif memproses (bukan idle).
Starvation
Proses tidak pernah dapat giliran CPU. Round Robin mencegah ini.
